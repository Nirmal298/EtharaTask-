Employment Management System. Full Stack Application Prompt

Context and function
I need to build a good Employment Management System. This system is for managing people at work. As the person in charge of building this system I have to make sure it is easy to use and works well. The Employment Management System must have an interface that people like to use. It has to be easy to get and work well on different devices.

The Employment Management System should have a page that shows all the important information about the people working at the company. This page should be easy to understand and help the people, in charge of hiring the heads of departments and the employees themselves. The Employment Management System should also have a way for people to talk to each other and send messages. When someone sends a message the system should keep a record of it. Send an email to the people who need to know. The Employment Management System is a deal and I want to make sure it is really good.


Objective
I want to make a website that shows all my work. This website should have
* animations that play when you scroll down the page using Framer Motion.
* a clean and modern design that looks good on any device and has movements.
* a button that says "Get in Touch" which opens a form to send me a message.
* a way to keep the messages people send me safe and private.
* a way to send me an email when someone fills out the form, on my portfolio website with the details they submitted on the portfolio website.

Backend Requirements

API Architecture

We need to have an API that has different versions. For example the version will be in the link like this: /api/v1/...
We will use something called JWT-based authentication. This means we will use a token to make sure only the right people can use our API. We will also make sure this token is changed regularly.
We need to make sure that only people with the role and permission can use the protected routes.
We have to keep a record of every API call. This record will have the method, endpoint, user and timestamp.

Data Processing Requirements

We have to make sure all the inputs are clean. This means we have to prevent something called XSS and SQL/NoSQL injection attacks.
We need to check all the date ranges email formats, phone numbers and numeric fields on the server.
We have to hash all the passwords. We will use something called b-crypt. We will do it at least 12 times.
We need to encrypt some fields. These fields are sensitive. They include the PAN number and bank account details. We will use something called AES-256 to encrypt these fields.
All the API responses have to be in a format. If it is successful it will look like this: { success: data: {... } Message: "Operation successful" }
If there is an error it will look like this: { success: false error: "Error description," code: 400 }
If we are getting a list of things, from the API it has to be paginated. This means it will look like this: { data, total, page limit }
We have to prevent spam and abuse. We will use something called rate limiting. We might also use CAPTCHA on public-facing forms. This will help us make sure that people are not using our API in a way.
